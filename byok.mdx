title: "Bring Your Own Keys"
description: "Use your own provider API keys through the varg API"
---

BYOK (Bring Your Own Key) lets you use your own provider API keys through the varg API. You still get caching, stable URLs, files with lineage, and the unified API — the AI generation runs against your provider account.

<Info>
**You still need a `VARG_API_KEY`** even with BYOK. It authenticates you with the varg API. BYOK changes which provider account runs the generation.
</Info>

## Why BYOK?

- **Provider-direct billing** — you pay the provider directly, at provider rates
- **Own quotas** — use your own rate limits and billing
- **Same API features** — caching, stable URLs, files, lineage, unified API
- **Mix and match** — use BYOK for some providers, varg credits for others

## How it works

Pass your provider key inside `provider_options.<provider>.apiKey` in the request body:

```bash
# Generate an image using your own Fal key
curl -X POST https://api.varg.ai/v2/image \
  -H "Authorization: Bearer $VARG_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "nano_banana_pro",
    "prompt": "sunset over mountains",
    "provider_options": {
      "fal": { "apiKey": "fal_xxx" }
    }
  }'
```

<Note>
Your provider keys are **encrypted immediately** on receipt and stripped from the stored job input — they are never persisted in plaintext and never appear when you read the job back.
</Note>

## Provider keys

| Provider | provider_options key | Env var | Get key at |
|----------|---------------------|---------|------------|
| Fal | `fal` | `FAL_KEY` | [fal.ai/dashboard/keys](https://fal.ai/dashboard/keys) |
| ElevenLabs | `elevenlabs` | `ELEVENLABS_API_KEY` | [elevenlabs.io/app/settings/api-keys](https://elevenlabs.io/app/settings/api-keys) |
| Higgsfield | `higgsfield` | `HIGGSFIELD_API_KEY` | [higgsfield.ai](https://higgsfield.ai) |

## Local render (TypeScript)

Pass provider keys when creating the varg client:

```tsx
/** @jsxImportSource vargai */
import { Render, Clip, Image } from "vargai/react"
import { createVarg } from "vargai/ai"

const varg = createVarg({
  apiKey: process.env.VARG_API_KEY!,
  providerKeys: {
    fal: process.env.FAL_KEY!,
    elevenlabs: process.env.ELEVENLABS_API_KEY!,
  },
})

const img = Image({
  model: varg.imageModel("nano_banana_pro"),
  prompt: "a cabin in mountains at sunset",
  aspectRatio: "16:9",
})

export default (
  <Render width={1920} height={1080}>
    <Clip duration={3}>{img}</Clip>
  </Render>
)
```

### .env setup for BYOK

```bash
# Required
VARG_API_KEY=varg_xxx

# BYOK provider keys (optional — only include the ones you have)
FAL_KEY=fal_xxx
ELEVENLABS_API_KEY=xxx
HIGGSFIELD_API_KEY=hf_xxx
```

## Caching with BYOK

BYOK requests use the same cache as pooled requests. The cache key is based on the request parameters (prompt, model, etc.), **not** the API key used.

This means:
- If a result is already cached from a previous pooled request, your BYOK request gets the cached result at $0
- If you generate something new with BYOK, subsequent requests (pooled or BYOK) get the cached result

## When to use BYOK vs credits

| Scenario | Use |
|----------|-----|
| Getting started, small projects | **Credits** — simplest, one key |
| High volume production | **BYOK** — use provider pricing directly |
| Need specific provider features | **BYOK** — full access via `provider_options` |
| Team with existing provider accounts | **BYOK** — reuse existing keys |
| Prototyping, learning | **Credits** — no provider setup needed |
